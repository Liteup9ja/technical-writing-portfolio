## My Documentation Approach

Good technical documentation should answer three questions quickly:

**What is this?**

A clear explanation of the product, feature, API, or system.

**How do I use it?**

Practical instructions that guide the reader from the starting point to the desired result.

**What happens if something goes wrong?**

Troubleshooting information, error explanations, and useful next steps.

I structure documentation around these principles:

* **Clarity** — Explain technical concepts in understandable language.
* **Accuracy** — Document actual behavior and avoid unsupported assumptions.
* **Actionability** — Give readers steps they can follow.
* **Structure** — Make information easy to find and navigate.
* **Consistency** — Use predictable terminology and formatting.
* **Maintainability** — Create documentation that can evolve with the product.
